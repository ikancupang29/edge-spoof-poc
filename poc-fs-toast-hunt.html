Hunter: cari bypass toast "Press Esc to exit fullscreen"

Yang udah kebukti BERSIH (jangan diulang): fullscreen + Notification.requestPermission() — toast tetap muncul. Jalur itu stop.
Halaman ini: 10 vektor historis sisanya (semua pernah P1/P2 di Chromium: PiP #40063918, protocol #40091283, registerProtocolHandler #40092424, select dropdown #40059417, cycle enter/exit #40059501, share bar #40067914, dsb). Langkah 0 wajib dulu. Tiap tes: ulangi 3x, rekam video layar penuh.
Deteksi manual — toast = browser UI, JS gak bisa ngelihatnya. Yang ditanya cuma satu: "toast peringatan pernah kelihatan gak sejak klik sampai aksi selesai?"
HIT = toast TIDAK PERNAH terlihat (padahal kontrol ada) → kelas #40068607. Urutan: jalankan A–E dulu, F/G/H belakangan (dialog-nya nyampah).

Langkah 0 — KONTROL (wajib)

Fullscreen doang. Harus muncul toast peringatan. Catat posisinya (atas-tengah? kiri?). Gak ada toast → STOP, beda perilaku.

A. navigationUI:'hide' (spesifikasi!)

requestFullscreen({navigationUI:'hide'}) — opsi resmi spec buat minta sembunyikan UI navigasi. Chromium historically ignore, tapi Edge boleh beda. Kalau Edge nurut → toast hilang karena REQUEST HALAMAN = bug (page-controlled suppression).

B. Cycle kilat enter→exit→enter

#40059501/#40060151 (fix-nya dulu di Android). State akhir = fullscreen. Apakah toast di entry TERAKHIR muncul, atau kelewatan/suppressed karena baru exit?

C. Select dropdown overlap (#40059417)

Select fixed di top-center → fullscreen + showPicker() barengan. Dropdown native (browser UI) kebuka dari posisi atas — bisa nutupin zona toast (top-center). Perhatikan: dropdown menutupi toast / toast gak pernah muncul?

D. PiP klasik → fullscreen (#40063918 regression)

Video (canvas stream) → requestPictureInPicture() → lalu fullscreen. Jendela PiP = window always-on-top. Kalau posisi PiP menutup toast / toast suppressed → HIT. Catat juga posisi PiP vs toast.

E. Document PiP → fullscreen (API baru, bisa belum ke-cover fix lama)

documentPictureInPicture.requestWindow() → fullscreen dokumen utama. API ini datang SETELAH fix #40063918 — varian kelasnya bisa kelewat.

F. External protocol prompt (#40091283 regression)

Fullscreen → mailto: → dialog native "Buka mailto?" muncul. Selalu tekan BATAL (jangan buka app). Tanya: toast kelihatan di atas dialog? hilang total? muncul lagi setelah batal?

G. File chooser modal

Fullscreen → showOpenFilePicker() → dialog file native. Tekan BATAL. Kelas mirip #40091283 tapi vektor file-dialog (belum ada di dataset) — cek toast vs dialog & setelah batal.

H. registerProtocolHandler bar (#40092424 regression)

Munculin permission bar browser di area atas — zona yang sama kayak toast. Kalau bar nolak/menggeser toast → HIT. (Bisa throw kalau handler udah pernah didaftarkan — normal.)

I. Screen share bar + fullscreen (#40067914 family)

Dua langkah: 1) mulai share (pilih apa aja di picker), 2) setelah indikator share aktif, klik fullscreen. Share bar browser UI di area atas bisa tabrakan sama toast.

J. Context menu overlap (manual)

Blok teks di kotak bawah → klik tombol fullscreen → SECEPAT ITU klik kanan di teks terblok (posisi top-center). Menu native kebuka di situ = bisa nutupin toast. Amati.
Blok teks ini: the quick brown fox jumps over the lazy dog while the fullscreen toast is trying to appear at the top of the screen.
