Tes: Notifikasi Fullscreen vs Dialog Permission (temuan fs-c)

Hipotesis: saat requestFullscreen() dan Notification.requestPermission() dijalankan di klik yang sama, notifikasi "Press Esc to exit fullscreen" tidak tampil / ketutup dialog izin → user masuk fullscreen TANPA peringatan → digabung fake address bar = phishing chrome palsu komplit.
Preseden: P1 #40057591 (permission dialog sembunyiin fullscreen alert), P1 #40068607 (Hide Fullscreen Notification), P1 #40064688 (autofill+fullscreen), P1 #40063918 (PiP), P2 #390571618 (permission dialog dismiss menipu status fullscreen).
Bedain: "Esc tetap bisa keluar" = BUKAN ukuran (itu selalu jalan). Yang diuji = toast peringatannya muncul & keliatan atau nggak. Rekam video LAYAR PENUH.
Langkah 1 — KONTROL (wajib dulu): fullscreen saja
Klik → layar fullscreen → harusnya muncul toast "Press Esc to exit fullscreen" (sekitar 1-4 detik, biasanya atas/tengah). Catat: muncul? posisi mana? berapa lama? Kalau kontrol aja gak ada toast → test INVALID (perilaku default beda), jangan dilanjut.
Langkah 2 — RACE: fullscreen + dialog izin notifikasi barengan
Klik → fullscreen masuk DAN dialog "izinkan notifikasi" muncul bersamaan → resolve dialog (Allow/Block) → perhatikan: toast peringatan fullscreen pernah keliatan gak selama situasi itu?
HIT: toast TIDAK PERNAH terlihat di video (padahal kontrol ada) ATAU habis masa-tampilnya tertutup penuh dialog → lapor P1/P2 kelas 40057591.
BUKAN BUG: toast tetap kelihatan (meski sebentar / sebagian).
Langkah 3 — CHAIN penuh (cuma kalau Langkah 2 = HIT): fake address bar
Rekaan dari fs-c: setelah dialog resolve, gambar chrome browser palsu (tab + google.com) disisip di atas → konten bawah = halaman phishing. Ini buat VIDEO demonstrasi dampaknya, bukan bukti terpisah. Untuk laporan nanti ganti domain jelas palsu (mis. acc0unts.google.com.verify-domain.xyz), jangan google.com beneran.
