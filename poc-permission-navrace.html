T2-A: Permission Prompt Origin Desync via Nav Race

Hipotesis: saat dialog permission (geolocation/notifikasi) terbuka, navigasi cross-origin dijalankan. Kalau origin di dialog, isi address bar, dan origin JS tidak konsisten satu sama lain = bug spoofing (preseden Chrome P1 #488762971 — "permission prompt salah origin saat UI/tab lain aktif").
Aturan SOUL: cross-origin wajib, ulang 5x, rekam video address bar SEBELUM + SESUDAH navigasi, test Edge Stable dulu → bandingkan Edge Canary. Origin sama = bukan bug.
Persiapan (wajib):
1. Buka Edge InPrivate (Ctrl+Shift+N) supaya keputusan permission selalu "tanya dulu".
2. Pastikan Edge → edge://settings/content/locations (dan notifications) dalam keadaan Ask (default).
3. Kalau pernah klik Allow/Block utk github.io di profile biasa, reset dulu — kalau tidak, dialog tidak akan muncul (test gagal, bukan bug).
4. Rekam video: zoom address bar, mulai rekam SEBELUM klik tombol.
Kontrol race

Ulang 5x manual: JALANKAN → observasi → tekan Back → JALANKAN lagi. (Loop otomatis tidak mungkin: halaman diunload saat nav, semua timer mati.) 




Checklist observasi (isi DENGAN video, jangan ngarang):

1. Saat address bar sudah menampilkan TARGET tapi dialog permission masih terbuka:
   teks origin di dialog = github.io / target / lainnya ?

2. Urutan: dialog menutup duluan atau bar berubah duluan?

3. Setelah commit: konten yang tampil = halaman attacker / error page / halaman target?

4. Klik ALLOW saat desync → cek ulang edge://settings/content/locations:
   izin tercatat untuk origin mana?
