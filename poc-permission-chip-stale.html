Kandidat #2: Permission Chip Stale setelah Navigasi Cross-Origin

Hipotesis: chip permission di omnibox (class asli PermissionChipView / PermissionDashboardController — ada di msedge.dll) menampilkan keputusan izin origin lama setelah tab pindah origin. Chip = UI browser (halaman tak bisa memalsukannya), jadi kalau salah setelah commit = kesalahan browser.
Penting: binary Edge punya HideChipAfterDelay → chip bisa hilang sendiri karena timer. Tanpa kontrol, test ini gampang salah baca. Urutan wajib: KONTROL dulu → baru eksperimen.
Kriteria HIT (semua syarat ini, jangan klaim kalau cuma sebagian):
H1: Setelah halaman target SELESAI load penuh (spinner berhenti, konten tampil), chip "Location allowed" github.io masih tampil di omnibox, padahal origin target tak pernah di-grant. Minimal 3 dari 5 percobaan, pakai 2 target berbeda.
H2: Chip masih ada → klik chip → bubble menyebut origin TARGET tapi state-nya berasal dari keputusan github.io (izin palsu utk origin tsb).
H3: Cek edge://settings/content/locations: izin github.io nyasar tercatat untuk origin target (permission leakage — kelas P1).

BUKAN BUG (jangan dilaporkan): chip hilang ≤1-2 dtk setelah commit (bisa HideChipAfterDelay — bandingkan dg KONTROL); chip cuma ada saat nav pending lalu hilang saat commit; hasil kontrol vs eksperimen sama; target ternyata sudah pernah di-grant (ganti target); prompt tak mau muncul = TEST INVALID, bukan bug → lapor balik ke gw, jangan klaim apa-apa.
STEP 0 — KONTROL (wajib, jalankan PERTAMA, tanpa navigasi):
Klik Kontrol → izinkan location → amati chip di omnibox kiri (sebelah URL):
a) Chip muncul? Y/N → kalau N = Edge tak menampilkan chip → STOP, test invalid.
b) Chip hilang sendiri setelah berapa detik? _____ dtk → ini baseline HideChipAfterDelay.
c) Dengan watchPosition aktif, chip bertahan terus atau tetap hilang? _____
Catat hasilnya sebelum lanjut ke eksperimen.
